# Evidence Standard

## Evidence maturity

- **C0 — Claim/opinion**
- **C1 — Source/documentation inspection**
- **C2 — Source code/tests**
- **C3 — Multiple independent implementations**
- **C4 — Reproduced**
- **C5 — Benchmarked**
- **C6 — Independently validated**
- **C7 — Production evidence**

## Confidence dimensions

Never reduce research quality to one score. Track evidence confidence, technical quality, research value, production readiness, reproducibility, novelty, maintenance health, license compatibility, security risk, complexity, relevance, reuse potential, and research cost as appropriate.

## Claim handling

A claim should identify its source, evidence, date/version, scope, limitations, and verification status. Contradictory claims should remain visible until the disagreement is explained or experimentally resolved.

## Provenance

The preferred chain is:

`Source → Claim → Implementation → Code location/version → Reproduction → Benchmark → Finding → Decision`

## Reproducibility

Record OS, language/runtime version, dependency versions, hardware, dataset/version, configuration, random seeds, parameters, and source commit whenever applicable.
